# d3studio — своя студия ассетов (план)

Решение владельца 09.11.2026: студия идёт **по Godot и Unity**; экспорт в файлы Disciples 3
(`.g`, `.scene`, `.ac`, `.a`) отложен — формат до конца не известен, изменённый ванильный юнит
роняет игру. Мост живёт в `studio/server/experimental/d3tool.mjs`, к студии не подключён.

Решение владельца 07.11.2026: хватит патчить чужую студию — делаем свою. Чужую сборку
(AstraForge 0.6.12) можно **смотреть**, чтобы понимать поведение: что такое задание,
как показывается прогресс, как выбирается чекпойнт, что пишется в провенанс. **Код, форматы
файлов и названия не копируются.** Всё своё пишется против двух публичных контрактов:

* **ComfyUI HTTP API** — `POST /prompt` (граф в «API format»), `GET /history/<id>`, `GET /view`,
  `/object_info`, `/interrupt`, `/free`. Он же у локального движка на `:8192`, он же у обычного
  ComfyUI на `:8188` — поэтому студия работает с любым из них и не зависит ни от чьей сборки.
* **наш собственный `d3tool` CLI** — `python -m d3tool export <glTF> -o <папка>`, уже проверенный
  на 84 из 84 юнитов (`tests/reverse_parity.py`).

Главное отличие от чужой студии: **результат — готовый пакет для движка**, а не одинокий GLB
«на вынос»: `Assets/<Имя>/` для Unity (модель + текстуры + манифест + инструкция импорта,
`studio/server/unity.mjs`) и папка Godot-пакета. Один и тот же меш уходит в оба движка без
пересборки, а манифест `d3studio.bundle.json` говорит, откуда файл и что в нём.

## Два режима

| Режим | Где | Что даёт | Запуск |
|---|---|---|---|
| **Полный** | `studio/` (Node + React, основа — MIT-версия 0.3.0, см. `BASE.md`) | 3D-конвейер, ракурсы, риггинг, VFX, спрайты, Unity-пакет (Godot-пакет — базовый) | `cd studio && npm ci && npm start` |
| **Лёгкий** | `d3studio/` (Python, только stdlib) | проекты, задания, SDXL-концепт, GLB-выгрузка, без npm и сборки | `python -m d3studio serve --open` |

Полный режим — основной; лёгкий остаётся для машины без Node и как проверяемая
эталонная реализация очереди/библиотеки.

## Что уже есть (M0, этот коммит)

| Модуль | Что делает |
|---|---|
| `d3studio/config.py` | настройки в `studio-data/settings.json`: адрес движка, чекпойнт, размеры, шаги, cfg, папка `d3tool`; мусор в файле не ломает запуск |
| `d3studio/store.py` | SQLite: проекты, ассеты, задания; прогресс и статус переживают перезапуск |
| `d3studio/comfy.py` | клиент ComfyUI API + **наш** граф SDXL (checkpoint → два текстовых кодировщика → пустой латент → сэмплер → декод → файл), размеры выравниваются по 8, seed замораживается |
| `d3studio/queue.py` | один рабочий поток: `queued → running → done/failed/cancelled`, отмена через флаг + `/interrupt` |
| `d3studio/pipeline.py` | задания `concept` (текст → PNG + JSON рядом с картинкой: промпт, seed, чекпойнт) и `export.d3` (GLB → файлы игры; в лёгком режиме остаётся) |
| `d3studio/api.py` | JSON API + раздача страницы; только `127.0.0.1` по умолчанию, защиты от выхода за папки |
| `d3studio/web/*` | одна страница: проекты, описание, параметры, задания с прогрессом, галерея, загрузка GLB, экспорт в D3 |
| `tests/test_studio.py` | 16 проверок на поддельном ComfyUI: граф, хранилище, сквозной концепт, отмена, ошибки движка, экспорт, HTTP API |

Запуск: `python -m d3studio serve --open` (или `d3studio serve --open` после `pip install -e .`).
Проверки: `python3 tests/test_studio.py`.

## Этапы дальше

**M1. Картинка → меш.** Нужен один шаг «концепт → GLB». Варианты под нашу карту (GTX 1080 Ti,
11 ГБ, Pascal, без bf16):
1. **ComfyUI + ноды Hunyuan3D 2.x** — то, что уже стоит у пользователя (`hunyuan3d-dit-v2`,
   `v2-mv`, `3d_v2.1` в `data\models\checkpoints`). Студия пишет свой граф под эти ноды, вес
   и качество известны. Минус: зависимость от чужих custom-нод.
2. **TripoSR** отдельным процессом — проверен на 6–8 ГБ, fp16, без bf16; запускается из студии
   как «внешний движок» с обменом файлами. Плюс: свой маленький воркер, никаких custom-нод.
3. **Импорт готового меша** — уже есть: `POST /api/projects/<id>/assets` (GLB руками из Blender).

Критерий выбора: на 11 ГБ уложиться в генерацию 512² с пиком ≤ 9 ГБ и не получить «0xC0000005»
на драйвере. Решение — по замеру, как с MV-Adapter.

**M1.4. Проверка модели перед импортом — сделано.** `POST /api/mesh/check` и отчёт внутри
Unity-пакета: треугольники, вершины, дубликаты, UV/нормали, скелет, клипы, границы, неравномерный
масштаб; блокеры не дают упаковать модель. 10 проверок.

**M1.5. Unity в интерфейсе — сделано.** На шаге «Экспорт» блок **Unity**: «Проверить модель»
(находки с уровнями) и «Скачать пакет для Unity» (собирает `.zip` и сразу отдаёт файл). Модель
берётся резолвером `server/model-source.mjs` из студии (`data/assets/`) или из библиотеки Кузницы
(`library/assets/<id>/<версия>/`), с проверкой, что путь не вылез за папку ассета.

**M1.5.1. Unity профилем экспорта.** Сейчас блок отдельный; чтобы он стал профилем рядом с Godot,
нужен шаг в конвейере Кузницы (`forge-steps.mjs`) — следующие шаги.

**M1.6. Нативная часть на Rust — начата.** `native/d3mesh`: проверка контейнера GLB и CRC32 одним
проходом, без зависимостей; JS-двойник и паритет-тест. Дальше по порядку: сварка вершин, децимация,
нормали, атласы, спрайт-листы (`docs/studio/NATIVE.md`).

**M2. Текстуры и материалы.** Атласы к мешу и PBR-набор под Unity/Godot: одна палитра, свои
имена карт (`_BaseMap`, `_Normal`, ORM), манифест уже перечисляет файлы с sha256.

**M3. Проект и стиль.** Пресеты (жанр, палитра, разрешение, чекпойнт), «серия» — один стиль на
несколько ассетов, история seed'ов, дубли рецептов.

**M4. Приёмка.** `tests/unity.test.mjs` проверяет состав пакета, байты модели и манифест;
дальше — то же для Godot-пакета и проверка импорта в самом движке (Godot 4.5 headless уже
умеет в базовой версии, Unity — только руками, пока не появится CI с лицензией).

**M5. Упаковка мода.** `.vdpack` (`d3tool vdpack pack`) — «собрать мод» одной кнопкой,
с `Aliases`, профилями `.char` и проверкой `vdpack validate`. Отложено вместе с Disciples:
делаем, когда формат подтвердится на живом юните.

## Чего не делаем

* Не копируем код и структуру чужой студии, не тащим её движок как зависимость.
* Не LR-им никаких внешних сервисов: только локальная карта и локальные файлы.
* Не обещаем обучение LoRA, пока не замерим его на 11 ГБ (см. отчёт по LoRA).
* Не трогаем формат Disciples 3, пока не будет известно, почему изменённый юнит роняет игру.

## Риски

| Риск | Что делаем |
|---|---|
| ComfyUI-ноды Hunyuan меняют имена входов | граф строится по `/object_info`, а не по зашитым именам — ошибка будет внятной |
| Windows-пути и кодировки | все подпроцессы с `PYTHONIOENCODING=utf-8`, файлы читаются `utf-8-sig` |
| Долгая генерация и перезапуск | статусы в SQLite, «прервано перезапуском» вместо вечного `running` |
| Видеокарта занята чужой студией | адрес движка — настройка; в планах — очередь с приоритетом и проверка занятости через `/queue` |
