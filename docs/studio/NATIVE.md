# Нативная часть студии (Rust)

Решение: тяжёлые вычисления по сеткам и файлам — в нативной части, на **Rust**. Язык выбран
по делу: один бинарник без рантайма, предсказуемая скорость, нет сборки мусора на 700 тыс.
треугольниках. Всё остальное (сервер, интерфейс, очередь) остаётся на Node/React — переписывать
студию целиком на Rust смысла нет, дорого и ничего не ускорит.

## Правило, по которому это живёт

1. Нативная часть — **ускорение, а не обязательное условие**. Если бинарник не собран, студия
   работает: тот же расчёт делает JS-двойник.
2. У каждого нативного шага есть **JS-двойник** (`server/native.mjs`) и **паритет-тест**:
   ответы обязаны совпадать байт в байт по смыслу (`tests/native.test.mjs`).
3. Никаких зависимостей в `Cargo.toml`: собирается без сети (`--offline`), без crates.io.
4. Нативная часть печатает **JSON одной строкой** в stdout и говорит кодами выхода
   (0 — годно, 1 — брак, 2 — неверный вызов). Никаких «магии» и скрытых файлов.

## Что уже есть (шаг 1)

| Файл | Что делает |
|---|---|
| `native/d3mesh/src/main.rs` | `d3mesh verify <файл.glb>`: проверяет контейнер (подпись, версия 2, длина, чанки JSON/BIN, паддинг) и считает CRC32 одним проходом по байтам |
| `native/d3mesh/Cargo.toml` | пустые зависимости, `opt-level = 3`, `lto`, `panic = "abort"` |
| `server/native.mjs` | JS-двойник той же проверки (`verifyGlbBuffer`), поиск бинарника, запуск (`nativeVerify`) |
| `scripts/build-native.mjs` | `npm run native:build` → `cargo build --release --offline`, честная ошибка, если cargo нет |
| `tests/native.test.mjs` | JS-проверка на годном и битых файлах; паритет с Rust — включается сам, когда бинарник собран |

## Как собрать у себя

```powershell
# один раз
winget install Rustlang.Rustup      # или https://rustup.rs
cd studio
npm run native:build                # cargo build --release --offline
npm test                            # паритет-тест перестанет пропускаться
```

Бинарник: `studio/native/d3mesh/target/release/d3mesh` (на Windows `d3mesh.exe`).
Ошибка сборки ничего не ломает: студия продолжит считать то же на JS.

## Почему шаг 1 не собран в этой песочнице

Проверено честно, а не «на глаз»:

* `rustup` в песочницу ставится из PyPI (`pip install rustup` → 1.29.0, 7,9 МБ), то есть
  менеджер тулчейнов есть;
* `rustup toolchain install stable` падает: `could not download file from
  'https://static.rust-lang.org/dist/channel-rust-stable.toml.sha256' … tls handshake eof` —
  этот хост закрыт, как и crates.io;
* `apt-get install rustc` — тоже сеть наружу, тот же тупик.

Поэтому в песочнице проверены JS-двойник и паритет-тест (сейчас он пропускается с точной
причиной), а компиляцию Rust делает машина с тулчейном — одна команда выше. Код Rust при этом
не «на веру»: тест паритета сравнивает поля `bytes`, `version`, `json_chunk`, `bin_chunk`, `crc32`
целиком, поэтому любое расхождение вылезет сразу после сборки.

## Что переносим дальше и в каком порядке

| № | Операция | Зачем нативно | Ожидаемый выигрыш |
|---|---|---|---|
| 1 | сварка вершин (weld) | сейчас считается на JS и только «на почитать» — запись нового GLB требует прохода по бинарю | десятки процентов вершин убираются, движок экономит память |
| 2 | децимация (упразднение по квадрикам) | главный тяжёлый шаг для LOD; на JS это секунды-минуты на 500 тыс. треугольников | LOD 1/2/3 на лету |
| 3 | нормали и тангенты | пересчёт по треугольникам, чистая арифметика | корректные нормали после децимации, без Blender |
| 4 | упаковка атласов текстур | полки/гильотина по битовым маскам | один материал вместо десяти |
| 5 | сборка спрайт-листов | композиция PNG без GPU | быстрее и без three.js |

Порядок выбран по пользе для Unity/Godot: 1 и 2 прямо влияют на то, что уезжает в движок,
3 закрывает шов после 2, 4–5 — уже про материалы и 2D.

## Как добавить следующий шаг (шаблон)

1. Команда в `native/d3mesh/src/main.rs`: `d3mesh <команда> <файл> [-o выход]`, JSON в stdout.
2. JS-двойник в `server/native.mjs` (или отдельном `server/*.mjs`) — обязателен.
3. В `tests/native.test.mjs` тест JS всегда, тест паритета — под `hasNativeBinary()`.
4. Строка в таблицу выше и в `studio/README.md`, абзац в `docs/studio/PLAN.md`.
