# Аудит: AstraForge 0.6.15 (последняя версия автора)

Дата: 09.11.2026. Что смотрели: `github.com/Snodrod/AstraForge`, тег `v0.6.15` (опубликован 09.11.2026, 11:56 UTC),
релизы 0.4.6–0.6.15 (33 выпуска в списке, более старые скрыты), наш базовый `v0.3.0`.

## Коротко

1. **Кода последней версии в открытом виде нет.** В репозитории лежит снимок **0.3.0**: `server/` (7 181 строка),
   `src/` (13 528), 24 файла тестов — те же файлы, что в теге `v0.3.0`, байт в байт. Последний коммит в `server/`
   — `cce8c29` от 18.10.2026, то есть ровно релиз 0.3.0.
2. **С 0.4.2 лицензия другая.** MIT остался только у 0.3.0; 0.4.2 и новее — PolyForm Noncommercial 1.0.0
   (бесплатно, без обновлений) или подписка 5 $/мес / 49 $/год (коммерческое использование + обновления).
   Об этом прямо написано в их README: «The source code in this repository is the older version 0.3.0 under the MIT
   License. Versions 0.4.2+ are distributed under the licenses above».
3. **Свежие версии — только бинарники:** `AstraForge-Setup-0.6.15.exe` (62,4 МБ) и `AstraForge-update-0.6.15.zip`
   (62,3 МБ) на релизе. В песочнице их скачать нельзя: GitHub отдаёт 302 на `release-assets.githubusercontent.com`,
   а этот хост закрыт (curl: `http=302`, затем обрыв). Аудит кода 0.6.15 поэтому **невозможен** — только по описаниям
   выпусков.
4. **Вывод для нас:** базой остаётся 0.3.0 (MIT) — это последняя версия, которую можно переписывать под себя.
   0.6.15 — источник идей и проверка, «что вообще бывает», и ничего больше: код закрыт, лицензия запрещает
   распространение и требует не убирать уведомления.

## Что автор реально сделал с 0.3.0 до 0.6.15 (по описаниям выпусков)

### Продукт

* **0.5.0 — свой движок вместо ComfyUI.** SDXL, Hunyuan3D (2.0 / 2mv / 2.1), MV-Adapter, Pixal3D, FLUX.2, Qwen-Image
  в одном процессе, модели не перезагружаются между шагами. Если новый движок не может выполнить задание,
  студия откатывается на ComfyUI. Это главный технологический шаг: они перестали быть надстройкой над ComfyUI.
* **0.5.0 — Unreal Engine 5** (ассеты + эффекты Niagara) рядом с Godot и Unity; подключение трёх движков из одного места.
* **0.6.10 — четвёртый движок: Bevy 0.20** — GLB + паспорт `af_bevy.json` (клипы, клип по умолчанию, точки крепления,
  коллайдер, эффекты) + крейт `astraforge_bevy`, одна строка в игре. Если Rust есть — студия сама проверяет ассет
  в Bevy без окна и снимает кадр.
* **0.6.0 — новые генераторы:** TripoSG (форма по одной картинке, хватает 8 ГБ — на таких картах основная),
  SkinTokens (авториг зверей/птиц/многоножек/грифонов, гуманоидов по-прежнему Blender), вкладка «Звук»
  (MOSS-SoundEffect, ACE-Step), «Стиль проекта» по 1–6 образцам, автоприёмка моделью Qwen3.5 (облёт против концепта,
  сама переделывает неудачные генерации).
* **0.5.0 — самообучение:** запоминает удачные настройки, может дообучать LoRA на принятых ассетах (с согласия).
* **0.5.0 — происхождение:** метка AstraForge (версия, лицензия) в каждой картинке и модели, у картинок — незаметный
  водяной знак. Старые файлы не трогают.
* **0.6.12 — встроенный модуль на Rust** для упрощения сеток: 700 тыс. треугольников ≈ 5 с вместо 10–20 минут
  (модели с ригом/шейпкеями/цветом вершин по-прежнему через Blender).
* **0.6.9 — два языка (RU/EN)**, выбор по локали Windows; **0.5.0 — интерфейс «Гибрид»**, тёмная/светлая темы,
  режимы «Просто» и «Подробно».

### Железо и установка (это и есть их основной поток работы — 25 из 33 выпусков про это)

* Поддержка 8 ГБ карт: ракурсы в 512 px, таймаут 20 минут, остановка задания в движке по «Отмене» и по таймауту
  (раньше карта продолжала считать часами); Pixal3D на C++ (~7 ГБ) вместо Python.
* AMD Radeon под Windows: установщик сам ставит PyTorch ROCm; при отсутствии ядра внимания — переход на обычное
  вычисление вместо падения.
* Окно «Компоненты»: проверка каждой программы и модели, наборы «Быстрая / Полная / Облегчённая», докачка без
  повторного запуска установщика; на 8 ГБ «Полная» не ставит то, что не влезет.
* Перед 3D-генерацией выгружают модели Ollama из видеопамяти; при занятой карте пишут об этом прямо.
* Загрузки: докачка с места обрыва, зеркала (hf-mirror вместо huggingface, второй адрес для Ollama, Godot, анимаций),
  проверка по контрольной сумме, повтор при 429, понятные причины вместо кодов ошибок Windows.
* Автообновления: с 0.4.9 бесплатные версии ставятся сами при следующем запуске, у подписчиков — сразу.

## Насколько это важно для нас (Godot + Unity)

Плюс: автор подтвердил наш вектор — **движков несколько, ассет один**, и «паспорт» ассета рядом с GLB.
Минус: всё, что он для этого сделал, закрыто; повторять придётся своим кодом.

Приоритет «взять идею, код свой» — по убыванию пользы для нас:

| № | Что у автора | Что у нас сейчас | Что делать |
|---|---|---|---|
| 1 | Паспорт ассета для движка: клипы, клип по умолчанию, точки крепления, коллайдер, эффекты (`af_bevy.json`), для Unity — ориентация и коллизии | `d3studio.bundle.json`: файлы + sha256 + версия Unity | добавить в манифест клипы, сокеты, коллайдер, `default_clip`; один формат на Godot и Unity |

| 3 | Пересчёт под железо: 8 ГБ, AMD, «не влезает — не ставим» | нет понятия бюджета VRAM | таблица «генератор → VRAM» в настройках, отказ до запуска с причиной; наш случай — GTX 1080 Ti 11 ГБ, Pascal без bf16 |

| 5 | Автоприёмка: VLM сравнивает облёт с концептом и переделывает | нет | после стабильного экспорта: 6 кадров облёта + концепт → вердикт «похоже/нет» с числом, без автопеределки на первом этапе |
| 6 | Происхождение и лицензии в ассете | нет | писать в манифест: чекпойнт, seed, лицензия модели-генератора, дата — без водяных знаков |

| 8 | Свой движок вместо ComfyUI | ComfyUI HTTP API | **не повторять сейчас**: свой движок — это годы; контракт ComfyUI нас устраивает |
| 9 | Водяные знаки, самообучение, подписка с привязкой к компьютеру, автообновления | — | не нужно: ни телеметрии, ни привязок, ни скрытых меток |

## Риски, которые аудит вскрыл (важнее списка фич)

1. **Лицензия Hunyuan3D не покрывает ЕС.** В их же `COMMERCIAL-LICENSE.md`: «the Tencent Hunyuan 3D license does
   not cover the European Union, the United Kingdom and South Korea». Мы работаем из Польши, то есть ЕС.
   Генерация 3D через Hunyuan3D для нас — вопрос лицензии, а не вкуса. Наш базовый конвейер (0.3.0) именно на нём.
   **Проверить до первой коммерческой сборки**: чем заменяем (TripoSG, Pixal3D/TRELLIS, TripoSR) и что пишем в
   манифесте ассета.
2. **SDXL и DINOv3 имеют ограничения использования** (там же). Наш лёгкий режим рисует SDXL — для внутренних
   экспериментов нормально, для продажи нужно смотреть условия.
3. **Источник обновлений не проверяем.** Автообновление с их сервера нам не нужно ни в каком виде; наш код обновляется
   только из нашего репозитория.
4. **README и выпуски противоречат друг другу:** в README бесплатная версия — «0.4.6, без обновлений», в описаниях
   0.4.9+ — «бесплатные обновления ставятся сами». Для нас это просто чужой маркетинг, но в переписке с пользователями
   автора не надо ссылаться на «бесплатную последнюю версию».
5. **Их «свой движок» значит, что наши патчи к 0.3.0-базе дальше не совместимы** с их 0.5+. Обновлять их сборку
   патчами (как `stab-4`, `models-3`) можно только для них и только под их версию; наша студия идёт своей веткой.

## Что проверить руками (когда понадобится)

1. Поставить 0.6.15 на Windows и снять с неё `update.zip` (62 МБ) — только для разбора поведения, не для кода:
   как устроен паспорт `af_bevy.json`, что именно кладётся в проект Unity, как считается коллайдер и ориентация.
2. Сверить наш `d3studio.bundle.json` с их паспортом по полям: клипы, сокеты, коллайдер, эффекты, лицензия.
3. Отдельно — лицензии генераторов: Hunyuan3D (ЕС!), SDXL, DINOv3, Pixal3D/TRELLIS. Решение записать в
   `docs/studio/BASE.md` или отдельным `LICENSES-MODELS.md`.

## Итог

Последняя версия автора — **0.6.15**, но открытого кода в ней нет: репозиторий остался на MIT-версии 0.3.0, а всё,
что сделано после, продаётся подпиской в бинарниках. Для нашей студии это ничего не меняет: базой остаётся 0.3.0,
направление — Godot и Unity (как и решено), а из их пути стоит перенять паспорт ассета, отправку в проект движка,
пересчёт под видеопамять и честные лицензии моделей. Всё это — своим кодом.
