# Что «по стандарту» у DeepSeek в OpenCode

Вопрос: какие настройки действуют на DeepSeek, если не трогать Zro и Coarena — то есть
что приходит из коробки. Ответ разбит на три слоя, потому что «стандарт» — это не одно число.

## Слой 1. Глобальные дефолты OpenCode

Действуют на **любую** модель, включая DeepSeek. Ничего не настраивал — значит вот это:

| Настройка | Дефолт | Что значит на практике |
|---|---|---|
| `compaction.auto` | `true` | сжатие истории включается само у края окна |
| `compaction.background` | `true` | summary пишется заранее; **неиспользованное тоже стоит денег** |
| `compaction.keep.tokens` | `15000` | после сжатия рядом с саммари остаётся ~15k свежих токенов |
| `compaction.buffer` | `"15%"`, минимум 16k | сжатие стартует при 85% заполнения окна |
| `tool_output.max_lines` | `2000` | столько строк вывода инструмента попадает в контекст |
| `tool_output.max_bytes` | `51200` | потолок 50 КБ на вывод инструмента |
| `settings.headerTimeout` | 5 минут | ждём заголовки ответа |
| `settings.chunkTimeout` | 15 минут | ждём следующий чанк стрима |
| `settings.timeout` | нет | общий таймаут запроса не ограничен |
| повторы | 3 раза | только на таймаут транспорта |
| `update` | `"notify"` | проверка обновлений, установка вручную |
| `model` | нет | если не задан — берётся «самая новая доступная» модель |
| `small_model` | деприкейт | фоновые задачи идут на модель сессии |

Для модели, которой нет в каталоге, OpenCode **выдумывает** такие лимиты:
контекст 200 000, выход 32 000, JSON-tools, текст и изображения на входе.

## Слой 2. Что даёт каталог для официального DeepSeek

Провайдер `deepseek` встроен, `@ai-sdk/openai-compatible`, API `https://api.deepseek.com`.
Ключ — через `/connect` → DeepSeek (`sk-...` с platform.deepseek.com).

| Модель | ID | Контекст | Выход | Цена вход/выход |
|---|---|---|---|---|
| V4.1 Flash 1017 | `deepseek-v4-flash` | 1 048 576 | 393 216 | $0.15 / $0.60 |
| V4.1 Flash 1017 (vision) | `deepseek-v4-flash-vision-exp` | 1 048 576 | 393 216 | $0.15 / $0.60 |
| V4.1 Flash (алиас) | `deepseek-flash` | 1 048 576 | 393 216 | $0.15 / $0.60 |
| V4 Pro 0813 | `deepseek-v4-pro` | 1 048 576 | 393 216 | $0.66 / $1.98 |

Заметь: у официального провайдера **нет** id `deepseek-v4.1-flash-1017`. Там
`deepseek-v4-flash`. Разные пулы называют одну модель по-разному, и это первая
причина ошибки `404`.

## Слой 3. Квирки, которые OpenCode включает сам

Это не настройки, которые ты ставишь, — это то, что OpenCode подставляет под DeepSeek
автоматически, потому что иначе API ответит ошибкой:

| Параметр | Значение для DeepSeek | Зачем |
|---|---|---|
| `maxTokensField` | `max_tokens` | DeepSeek не понимает `max_completion_tokens` |
| `reasoningField` | `reasoning_content` | там лежит цепочка рассуждений в стриме |
| `requireReasoning` | `true` | поле шлётся в каждом прошлом ответе ассистента, пустой строкой если рассуждений не было |

То есть DeepSeek — один из немногих провайдеров, для которых OpenCode имеет
жёстко прописанные исключения. Если поставить DeepSeek за прокси и он начнёт
ломаться на `max_tokens`, лечится вручную:

```json
{
"provider": {
  "deepseek": {
    "models": {
      "deepseek-v4-flash": {
        "compatibility": { "maxTokensField": "max_tokens" }
      }
    }
  }
}
}
```

## Что это значит на практике

Стандартные настройки для DeepSeek — **самые дорогие из всех твоих пулов**:

| | Стандарт | Бюджет |
|---|---|---|
| Контекст | 1 048 576 | 131 072 |
| Порог сжатия | ~891k (85% от 1M) | ~105k |
| Выход | 393 216 | 16 384 |
| Вывод инструмента | 2000 строк / 50 КБ | 600 строк / 16 КБ |
| Вход за прогон (25 ходов) | ~4–6M токенов | ~1,2–1,5M |

Официальный DeepSeek дешевле Zro по прайсу ($0.15 против $0.30 за вход), но
стандартный контекст в 1M съедает эту разницу: прогон выходит ~$0.9 вместо ~$0.2.

## Как урезать официальный DeepSeek

Ключ и адрес уже в каталоге, поэтому блок короткий — только лимиты, без `npm` и `baseURL`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "deepseek": {
      "models": {
        "deepseek-v4-flash": {
          "limit": { "context": 131072, "output": 16384 }
        },
        "deepseek-v4-pro": {
          "limit": { "context": 131072, "output": 16384 }
        }
      }
    }
  },
  "compaction": {
    "auto": true,
    "keep": { "tokens": 8000 },
    "buffer": "20%"
  },
  "tool_output": {
    "max_lines": 600,
    "max_bytes": 16000
  }
}
```

Этот блок можно вставить рядом с `coarena` и `zro` — конфликта нет, ключи `models`
переопределяют только перечисленные модели.

## Ещё один рычаг: кто пишет саммари

`compaction.background: true` означает, что summary пишется заранее, **и платится
за него даже если он не понадобился**. По умолчанию его пишет модель сессии — то есть
сам DeepSeek по $0.60 за выход. Можно отдать это дешёвой или бесплатной модели:

```json
{
"agents": {
  "compaction": { "model": "opencode/glm-5.3-flash-free" }
}
}
```

Если такого пула нет — оставь как есть. Если есть Zen, это экономит заметную часть
расхода: саммари — это полный контекст на выходе, самый дорогой запрос в сессии.

## Сводка

- **«По стандарту»** = глобальные дефолты из слоя 1, они одинаковы для всех провайдеров.
- **DeepSeek из каталога** = 4 модели, 1M контекст, 393k выход, $0.15/$0.60.
- **Автоматически** OpenCode правит под DeepSeek три квирка (`max_tokens`,
  `reasoning_content`, `requireReasoning`).
- **Дефолт не значит дешёвый**: 1M контекста при `buffer: "15%"` — это сжатие
  на ~891k, то есть почти никогда. Ровно та же ловушка, что была с Zro.
