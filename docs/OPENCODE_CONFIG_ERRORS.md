# Разбор ошибок в присланном `opencode.json`

Файл: 57 строк, **8 из них битые** — строки 2, 8, 9, 22, 23, 49, 50, 51.
Три класса ошибок, два разных последствия.

## Класс 1. Невалидный escape `\_` — 7 вхождений в 5 строках

Символ `_` не требует экранирования в JSON. `\_` не является допустимой
escape-последовательностью, поэтому парсер останавливается на первом же.

| Строка | Что написано |
|---|---|
| 9 | `"apiKey": "ВСТАВЬ\_КЛЮЧ\_COARENA"` |
| 23 | `"apiKey": "ВСТАВЬ\_КЛЮЧ\_ZRO"` |
| 49 | `"tool\_output": {` |
| 50 | `"max\_lines": 600,` |
| 51 | `"max\_bytes": 16000` |

Сообщение парсера:

```
Invalid \escape: line 9 column 26 (char 306)
```

**Последствие:** файл не парсится **вообще**. OpenCode молча берёт пустой конфиг —
ни Coarena, ни Zro, ни лимитов. Это самый опасный класс: ошибки не видно,
просто ничего не работает, и легко решить, что «ключ не подошёл».

Семь вхождений: два в строке 9, два в 23, по одному в 49, 50, 51.

Важно: падение происходит на строке 9, но строки 49–51 тоже битые — до них
парсер просто не доходит. Лечить надо все пять, а не одну.

## Класс 2. Markdown-ссылки вместо URL — 3 вхождения

| Строка | Что написано |
|---|---|
| 2 | `"$schema": "[https://opencode.ai/config.json](https://opencode.ai/config.json)"` |
| 8 | `"baseURL": "[https://coarena.ai/api/v1](https://coarena.ai/api/v1)"` |
| 22 | `"baseURL": "[https://zro.moonmath.ai/v1](https://zro.moonmath.ai/v1)"` |

Это **валидный JSON** — строка корректная, просто внутри мусор. Если бы не класс 1,
файл бы распарсился, и получилось бы худшее: тихая неправильная работа.

Что именно лежит в значении:

```
разбор urlparse:
  схема: ''   хост: ''   путь: '[https://coarena.ai/api/v1](https://coarena.ai/api/v1)'
```

То есть `baseURL` — не URL. Схемы нет, хоста нет, весь путь — литерал со скобками.
Запрос уйдёт в никуда, а ошибка будет выглядеть как сетевая, а не как опечатка
в конфиге. `$schema` безвреден (это подсказка редактору), а вот `baseURL` — фатален.

## Класс 3. Заглушки вместо ключей

`ВСТАВЬ_КЛЮЧ_COARENA`, `ВСТАВЬ_КЛЮЧ_ZRO` — 10 нелатинских символов в каждом.

Обычный placeholder, если бы не одно: HTTP-заголовок `Authorization` кодируется
как ByteString, а туда попадают только байты 0–255. Проверено в node:

```
TypeError: Cannot convert argument to a ByteString
because the character at index 7 has a value of 1050
```

**Последствие:** падение не с «неверный ключ», а с ошибкой кодировки — искать
причину в этом сообщении невозможно. Ключи только латиница и цифры.

## Что НЕ было ошибкой

Проверил отдельно, всё верно:

| Проверка | Результат |
|---|---|
| ключи верхнего уровня | `$schema, provider, model, compaction, tool_output, agents` — все есть в схеме |
| `buffer: "20%"` | совпадает с паттерном `^([1-9]\d?(\.\d+)?)%$` |
| `model` формат | `provider/model`, верно |
| `limit` у всех трёх моделей | обязательные `context` и `output` на месте |
| `model` → существующая модель | да |
| `agents.compaction.model` → существующая модель | да |
| id `opencode/deepseek-v4.1-flash-free` | реальный, есть в каталоге models.dev |
| `steps: 120` | правильное значение (60 было мало) |
| структура `provider` | один объект, два+1 провайдера внутри — верно |

## Итог в двух строках

- **Класс 1** — файл не запускается, но это громко и заметно.
- **Класс 2** — тихая поломка: конфиг загрузится, а запросы уйдут в никуда.

Второе опаснее первого, поэтому чистить надо оба, а не только escape.

## Как не повторять

Причина не в руках: текст идёт через чат, и рендер сам расставляет `](...)` и `\_`.
Три способа обойти:

1. **Скрипт-генератор** `docs/opencode-generate.ps1` — собирает JSON из объектов,
   а не из текста, поэтому искажать нечего.
2. **Копирование из файла** `docs/opencode.example.json` в репозитории.
3. **Проверка после записи**: `python tools/check_opencode_config.py <путь>`

Любой из трёх даёт `итог: без замечаний`, кроме незаменённых ключей.
