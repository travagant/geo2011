# Правила работы в этом репозитории

Файл читает любой coding-агент (OpenCode, Codex, Cursor) до первой правки.
Цель — не дать агенту сжечь контекст на обход 2 ГБ ассетов.

## Что это за проект

`d3tool` — конвертер ассетов «Disciples 3» ↔ glTF/Blender. Bpy-аддон собирается
в `release/`. Тесты — в `tests/`, документация — в `docs/`.

## Главное правило: не обходить репозиторий

Репозиторий 2 ГБ: 6934 файла, из них 286 `.dds` и 752 `.t` по 5 МБ каждый.
Попытка «найти, где это лежит» через `ls -R`, `grep -r` по корню или чтение файлов
целиком съедает лимит пула за один запрос.

**Работай по явному списку файлов.** Ядро задачи — семь файлов:

| Файл | Строк | Зачем |
|---|---|---|
| `d3tool/cli.py` | 3763 | экспорт, `_export`, имена `.ac` |
| `d3tool/gltf.py` | 2306 | чтение glTF, `_morph_trailing` |
| `d3tool/vdpack.py` | 1687 | упаковка `.vdpack` |
| `d3tool/gfile.py` | 1361 | бинарный формат `.g` |
| `d3tool/gltf_out.py` | 1230 | сборка glTF на выходе |
| `d3tool/texture.py` | 1130 | DDS, `_shrink_texture` |
| `tests/test_d3tool.py` | 6173 | тесты, 200 проверок |

## Запрещено читать целиком

Не открывай эти пути без прямой необходимости — они бинарные и огромные:

```
*.dds  *.t  *.bin  *.rar  *.png  *.jpg
Blender/  Empire/  Neutrals/  gltf/  out_rev/
```

Если нужно понять содержимое ассета — есть `d3tool/parse_dds.py` и тесты, а не
чтение байтов глазами.

## Как искать

Вместо `grep -r` по корню — точный поиск по коду:

```powershell
rg "def _export" d3tool/
rg -n "_morph_trailing" d3tool/gltf.py
```

Вместо чтения файла целиком — диапазон строк:

```powershell
(Get-Content d3tool/cli.py)[855..880]
```

## Тесты

В этом репозитории **pytest не установлен**, тесты — обычные Python-скрипты
с собственной функцией `main()`. Запуск без пайпа (пайп съедает код выхода):

```powershell
python tests/test_corpus.py        # ~73 секунды, 16 проверок
python tests/test_d3tool.py        # 200 проверок
```

Вывод `test_corpus.py` — 61 строка, влезает в `tool_output.max_lines` целиком,
ничего важного не обрезается. Строки `... .ac was not produced` — не падение,
а ожидаемый лог по задачам 1–2.

`test_d3tool.py` — 200 проверок, вывод длиннее. Запускать точечно нельзя
(pytest-фильтров нет), поэтому перед прогоном чисти рабочие артефакты:

```powershell
Remove-Item -Recurse -Force out_rev -ErrorAction SilentlyContinue
python tests/test_d3tool.py
```

Сгенерированный `out_rev/` идёт мимо `AGENTS.md`-правил и в анализ не включается.

## Формат правок

- Python 3.11+, только stdlib в `d3tool/` (без новых зависимостей).
- Все пути на Windows — через `pathlib`, не через `os.path` со слэшами.
- Кодировка файлов — UTF-8, при печати в консоль — через обёртку из `cli.py`.

## Что считается готовым результатом

Правка принимается, если:

1. `python tests/test_corpus.py` — 16/16 (сейчас 13/16 на задачах 1–2, это известное
   состояние, а не регрессия);
2. `python tests/test_d3tool.py` — 200/200;
3. импорт аддона проходит (`addon_import_test`);
4. в `docs/` обновлён отчёт, если менялось поведение.

## Стиль ответа

Коротко, по-русски, без пересказа диффа. Если тест упал — показать последние
10 строк вывода, а не весь лог.
