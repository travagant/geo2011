# Мост AstraForge → Disciples III: быстрый старт

Коротко: студия делает **GLB**, игра его не читает. Мост прогоняет GLB через
наш аддон Blender (получаются `.g/.scene/.ac/.a/.t`) и заворачивает результат в
`.vdpack` — единственный формат, который игра принимает как замену
(`docs/FORMATS.md` §6h). Студию мы **не трогаем** и не форкаем.

Работать можно двумя способами. Первый — «Арена подключается к тебе» — для него
ничего вводить в консоль не нужно, только двойной клик и одна строка в чат.

---

## Способ 1 (основной): Арена сама подключается к студии

Схема: на твоём ПК поднимается маленький сервер (`studio_link.py`), к нему
открывается временный туннель Cloudflare, и Арена дёргает его запросами. Студия,
GPU и файлы остаются у тебя; наружу уходит только ответ на конкретный запрос.
Туннель живёт, пока открыто окно.

### Что сделать один раз

1. Скачай архив репозитория (браузер, одна кнопка):
   `https://codeload.github.com/travagant/geo2011/zip/refs/heads/arena/5148e420-geo2011`
2. Распакуй, например, в `D:\geo2011` (главное — без пробелов и кириллицы в пути).
3. Открой папку `D:\geo2011\bridge`.
4. Двойной клик по **`Start studio link.cmd`**.

Скрипт сам: найдёт Python (или Python из студии), создаст `bridge\config.json`,
запустит сервер, один раз скачает `cloudflared.exe` (~35 МБ), откроет туннель,
**проверит его снаружи** и покажет примерно такое:

```
=============================================================
 Адрес : https://quiet-lake-1234.trycloudflare.com
 Токен : Kd8x…
 Скопировано в буфер. Вставь это в чат одной строкой:
   link https://quiet-lake-1234.trycloudflare.com Kd8x…
=============================================================
```

5. Вставь эту строку `link … …` в чат. Всё, канал есть.

Если Windows спросит про брандмауэр — разрешать **не нужно**: сервер слушает
только `127.0.0.1`, наружу ходит сам `cloudflared`.

Строку копируй **только после** «Канал проверен: адрес отвечает снаружи».
Если написано «Канал не поднялся» — скрипт уже попробовал HTTP/2 вместо QUIC;
он положит отчёт в `bridge\.link\last-attempt.txt`, пришли этот файл в чат.
Окно само не закроется: в конце всегда `pause`.

### Что дальше происходит в чате

Я по этому адресу могу: посмотреть список ассетов и свежих GLB, запустить
генерацию в студии, посмотреть её шаги и логи, прочитать любой файл в репо,
папке студии, донор-юните и `Mods`, запустить экспорт в Blender, собрать
`.vdpack` и прогнать гейт `vdpack scan`. Всё видно в `bridge\.link\log.txt`
(одна строка на запрос).

Когда закончили — вернись в окно и нажми Enter: туннель и сервер закроются,
канал перестанет существовать.

### Проверить, что живой

В окне, где запущен скрипт, есть ссылка вида
`http://127.0.0.1:3211/cmd?token=…&op=hello` — открой её в браузере, увидишь
JSON с путями и версиями.

## Способ 2: сам, без туннеля

В папке репозитория:

```bat
py bridge\astra_d3.py config          :: создать bridge\config.json и вписать пути
py bridge\astra_d3.py doctor          :: что найдено и заведётся ли на этой карте
py bridge\astra_d3.py run             :: свежий GLB -> .g -> Mods\<имя>.vdpack
py bridge\astra_d3.py watch --interval 10
```

Три значения в `config.json` надо вписать руками:

- `donor` — папка ванильного юнита, например
  `...\resources\characters\empire\inquisitor`;
- `mods` — папка `Mods` игры;
- `reference_pack` — рабочий `.vdpack` (например `ruru.vdpack`), по его индексу
  строится наш.

## Текстурный вопрос (важно понять заранее)

Мост **не рисует** `.dds`: как и при ручном экспорте, текстура берётся из
донора, а наша геометрия наследует её имя. «Своя» картинка из студии попадёт в
игру только после `d3tool texture` (png/tga → `.t`) и переименования парта —
это отдельный шаг, о нём скажешь отдельно.

## Если что-то не так — таблица

| Что видно | Причина и что делать |
| --- | --- |
| `НЕ НАЙДЕН Python` | Поставь Python 3.10+ с python.org, галочка «Add python.exe to PATH», перезапусти `.cmd`. Либо сначала поставь в студии компонент ComfyUI — у него свой Python. |
| `Сервер не поднялся` | Смотри `bridge\.link\server.err.log`: обычно занят порт 3211 (закрой старое окно) или путь с пробелами/кириллицей. |
| `Не скачалось` (cloudflared) | Скачай `cloudflared-windows-amd64.exe` из раздела Releases проекта cloudflare/cloudflared и положи как `bridge\.link\cloudflared.exe`. |
| Туннель не отдал адрес | Нет доступа к Cloudflare (корпоративный/провайдерский блок). Проверь VPN/файрвол; в крайнем случае используй способ 2. |
| В чате адрес «не отвечает» | Окно с `.cmd` закрыто — туннель умер. Запусти снова, адрес будет другой. |
| `blender not found` | Впиши `blender` в `bridge\config.json`. Если студийный Blender 5.0 падает на аддоне — поставь 4.2 LTS и укажи её. |
| `the GLB has no mesh data` | В студии сначала «Generate 3D», потом Export. |
| `no kernel image is available` | torch `cu128` на 1080 Ti: в нём нет кода для Pascal (`sm_61`). Двойной клик по `CUDA-check.cmd` — он скажет, какое окружение виновато; затем `CUDA-fix-torch.cmd` поставит torch `cu126`. Подробно — раздел «CUDA» ниже. |
| `str_not_valid_hash_for_file` в игре | Мод собран не через `vdpack` (loose-файлы) или без `--like`. Мост такой пак не пропустит — гейт `vdpack scan` вернёт ошибку. |
| `intersects other mods` | В `Mods` два мода с одинаковыми путями. |
| мод есть, юнита нет | В `user.ini` нет `sModifications=mod:<имя>` (имя = имя файла `.vdpack`). |

## Что мост НЕ делает

- не чинит драйверы, torch и ComfyUI;
- не обходит лицензии: Hunyuan3D-2 — Tencent Community Licence (в ЕС/UK/Южной
  Корее не действует), Pixal3D требует RTX 30/40/50 — на 1080 Ti недоступен;
- не меняет файлы в папке студии, кроме `data\runtime\d3bridge` (отчёты сборки).

## 5. CUDA: «no kernel image is available for execution on the device»

Это значит: **программа, которую вызвали, не содержит машинного кода для твоей
видеокарты**. 1080 Ti — это Pascal, `sm_61`. Карта исправна, виноват файл,
собранный без Pascal. Виноватых может быть ровно два, и падают они в разные
моменты:

| кто | почему | когда падает |
| --- | --- | --- |
| **torch** | сборки `cu128` содержат коды только для `sm_70` и новее; `cu126` — последняя линейка с Pascal. При этом `torch.cuda.is_available()` честно отвечает `True`, поэтому студия запускается и выглядит здоровой | на первом же тензоре — **модель даже не начинает строиться** |
| **`custom_rasterizer_kernel` из Hunyuan3D** | готовые wheel'ы собраны под Ampere и новее | модель строится, падает **текстура** (в стеке видно `PyInit_custom_rasterizer_kernel`) |

Какой случай у тебя, покажет один двойной клик:

1. **`bridge\CUDA-check.cmd`** — проходит по всем python.exe студии, честно
   запускает ядро на GPU (`torch.zeros(8).cuda()+1`, а не просто «CUDA
   доступна») и пишет `bridge\cuda-report.txt`. В отчёте по каждому окружению:
   версия torch, сборка CUDA, arch list, вердикт `[OK] / [БЕДА] / [!]`.
2. Если `[БЕДА]` — двойной клик по **`bridge\CUDA-fix-torch.cmd`**. Он спросит
   по каждому окружению и поставит torch/torchvision/torchaudio из
   `https://download.pytorch.org/whl/cu126`. Скачается ~2.5–3 ГБ, ставится
   ~7 ГБ, прерывать нельзя. Рабочие окружения (где ядро уже бегает) он не
   трогает.
3. Перезапусти студию и попробуй снова. Если модель строится, а падает только
   текстура — это второй случай, нужен `CUDA-fix-rasterizer` (пересборка
   `custom_rasterizer` под `6.1`); для него нужны CUDA Toolkit 12.x и MSVC
   Build Tools. Скажи мне — соберём пошагово.
