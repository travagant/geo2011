# Мост AstraForge → Disciples III: быстрый старт

Коротко: студия делает **GLB**, игра его не читает. Мост прогоняет GLB через
наш аддон Blender (получаются `.g/.scene/.ac/.a/.t`) и заворачивает результат в
`.vdpack` — единственный формат, который игра принимает как замену
(`docs/FORMATS.md` §6h). Студию мы **не трогаем** и не форкаем.

Работать можно двумя способами. Первый — «Арена подключается к тебе» — для него
ничего вводить в консоль не нужно, только двойной клик и одна строка в чат.

---

## Способ 1 (основной): Арена сама подключается к студии

Схема: на твоём ПК поднимается маленький сервер (`studio_link.py`), к нему
открывается временный туннель Cloudflare, и Арена дёргает его запросами. Студия,
GPU и файлы остаются у тебя; наружу уходит только ответ на конкретный запрос.
Туннель живёт, пока открыто окно.

### Что сделать один раз

1. Скачай архив репозитория (браузер, одна кнопка):
   `https://codeload.github.com/travagant/geo2011/zip/refs/heads/arena/5148e420-geo2011`
2. Распакуй, например, в `D:\geo2011` (главное — без пробелов и кириллицы в пути).
3. Открой папку `D:\geo2011\bridge`.
4. Двойной клик по **`Start studio link.cmd`**.

Скрипт сам: найдёт Python (или Python из студии), создаст `bridge\config.json`,
запустит сервер, один раз скачает `cloudflared.exe` (~35 МБ), откроет туннель,
**проверит его снаружи** и покажет примерно такое:

```
=== AstraForge <-> Arena: studio link ===
сборка  : 10
python  : C:\AstraForge\runtime\python\python.exe
папка   : D:\geo2011\bridge
студия  : C:\AstraForge
сервер  : http://127.0.0.1:3211  (только этот ПК)
сервер отвечает локально: OK
...
=============================================================
 Адрес : https://quiet-lake-1234.trycloudflare.com
 Токен : Kd8x…
 Сборка: 10  (папка D:\geo2011\bridge)
 Строка для чата:
   link https://quiet-lake-1234.trycloudflare.com Kd8x…
=============================================================
```

**Первое, что смотреть в окне — `сборка`.** Если номер меньше того, что
обещал чат, ты запустил старую распаковку (обычно ту, что лежит внутри
`D:\AstraForge\bridge`, — она осталась с прошлых сборок). Мост сам
предупреждает, если его папка находится внутри папки студии.

5. Вставь эту строку `link … …` в чат. Всё, канал есть.

   Не хочешь копировать — рядом появляется файл **`bridge\.link\SEND-ME.txt`**
   с этой же строкой внутри: перетащи его в чат, этого достаточно. В нём же
   лежат `build:`, `url:`, `token:` и `verdict:` — по ним сразу видно, ту ли
   сборку запустили и проверен ли канал.

Если Windows спросит про брандмауэр — разрешать **не нужно**: сервер слушает
только `127.0.0.1`, наружу ходит сам `cloudflared`.

Строку копируй **только после** «Канал проверен: адрес отвечает снаружи».
Если написано «Канал не поднялся» — скрипт уже перебрал все способы; он положит
отчёт в `bridge\.link\last-attempt.txt`, пришли этот файл в чат. Окно само не
закроется: в конце всегда `pause`.

Способы выхода, в этом порядке: **cloudflared QUIC → cloudflared HTTP/2 →
ssh через pinggy (порт 443) → ssh через localhost.run**. Для двух последних
нужен `ssh.exe` — он есть в Windows 10/11 (`C:\Windows\System32\OpenSSH`),
даже если его нет в PATH; скрипт сам находит этот путь.

### Если канал не поднялся — что означает строка отчёта

| строка | что было | что стало |
| --- | --- | --- |
| `local: not reachable (HTTP 403)` | на этом порту уже отвечал **другой, старый запуск моста** со своим токеном. Windows разрешает двум процессам «занять» один порт (`SO_REUSEADDR`), и новый запуск разговаривал со старым | порт проверяется подключением, а не занятием; если ответил чужой — берётся следующий порт, а в отчёт пишется, какой именно был занят |
| `verdict: not reachable (HTTP 1033)`, `530` | адрес брался из **старого лога** туннеля, то есть у мёртвого туннеля: Cloudflare отвечает «tunnel not found» или «origin unreachable» | лог туннеля обнуляется перед запуском, поэтому адрес всегда от текущей попытки |
| `verdict: local-fail` | сервер не смог ответить сам себе | при 403 больше не сдаётся: переходит на следующий порт |
| `verdict: unverified` | туннель поднялся, но с этой машины не проверяется | туннель остаётся живым — пришли строку `link …`, я проверю со своей стороны |

Отчёт всегда содержит `сборка:` и `папка:` — по этим двум строкам видно, ту ли
копию ты запустил.

### Что дальше происходит в чате

Я по этому адресу могу: посмотреть список ассетов и свежих GLB, запустить
генерацию в студии, посмотреть её шаги и логи, прочитать любой файл в репо,
папке студии, донор-юните и `Mods`, запустить экспорт в Blender, собрать
`.vdpack` и прогнать гейт `vdpack scan`. Всё видно в `bridge\.link\log.txt`
(одна строка на запрос).

Когда закончили — вернись в окно и нажми Enter: туннель и сервер закроются,
канал перестанет существовать.

### Проверить, что живой

В окне, где запущен скрипт, есть ссылка вида
`http://127.0.0.1:3211/cmd?token=…&op=hello` — открой её в браузере, увидишь
JSON с путями и версиями.

## Способ 2: сам, без туннеля

В папке репозитория:

```bat
py bridge\astra_d3.py config          :: создать bridge\config.json и вписать пути
py bridge\astra_d3.py doctor          :: что найдено и заведётся ли на этой карте
py bridge\astra_d3.py run             :: свежий GLB -> .g -> Mods\<имя>.vdpack
py bridge\astra_d3.py watch --interval 10
```

Три значения в `config.json` надо вписать руками:

- `donor` — папка ванильного юнита, например
  `...\resources\characters\empire\inquisitor`;
- `mods` — папка `Mods` игры;
- `reference_pack` — рабочий `.vdpack` (например `ruru.vdpack`), по его индексу
  строится наш.

## Текстурный вопрос (важно понять заранее)

Мост **не рисует** `.dds`: как и при ручном экспорте, текстура берётся из
донора, а наша геометрия наследует её имя. «Своя» картинка из студии попадёт в
игру только после `d3tool texture` (png/tga → `.t`) и переименования парта —
это отдельный шаг, о нём скажешь отдельно.

## Что мост НЕ делает

- не чинит драйверы, torch и ComfyUI;
- не обходит лицензии: Hunyuan3D-2 — Tencent Community Licence (в ЕС/UK/Южной
  Корее не действует), Pixal3D требует RTX 30/40/50 — на 1080 Ti недоступен;
- не меняет файлы в папке студии, кроме `data\runtime\d3bridge` (отчёты сборки).

## 5. «CUDA error: no kernel image is available for execution on the device»

Это значит ровно одно: **вызванная CUDA-программа не содержит машинного кода
для твоей карты**. 1080 Ti — это Pascal, `sm_61`. Карта исправна, виноват файл,
собранный без Pascal. Драйвер, CUDA Toolkit и настройки студии тут ни при чём.

### Откуда берётся неправильный torch

Причина не в тебе, а в установщике студии. `installer/Install.ps1`,
функция `InstallComfyDeps`, выбирает индекс колёс по одному признаку — «есть ли
видеокарта»:

```powershell
$torchIndex = if ($hasGpu) { 'https://download.pytorch.org/whl/cu128' } else { '.../cpu' }
uv pip install --python <venv> torch torchvision torchaudio --index-url $torchIndex
```

`cu128` — линейка **без Pascal** (там только `sm_70` и новее). Поэтому на 1080 Ti
ставится torch, который на этой карте не работает вообще. В репозитории студии
это записано и в `ai/skills/astraforge/references/components.md`: «PyTorch
**unpinned** … from `download.pytorch.org/whl/cu128`».

Самое неприятное — это тихо: `torch.cuda.is_available()` отвечает `True`,
ComfyUI стартует, модели грузятся, студия выглядит здоровой. Падает первый же
вызов ядра. Отличить легко по дампу `/api/status`: `gpu.vram_total` есть, а
`torch_vram_total: 0` — значит torch ещё ни разу не выделял память.

### Где именно этот torch лежит

Студия запускает Hunyuan3D в **своём** ComfyUI: `<студия>\runtime\ComfyUI`,
python — `runtime\ComfyUI\.venv\Scripts\python.exe` (`server/storage.mjs`,
ключ `comfyDir` в `data\config.json` может указывать в другое место). Чинить
надо именно это окружение — остальные python.exe к генерации отношения не имеют.

Вторая засада: это окружение создано командой `uv venv`, а **в нём нет pip**
(`python -m pip` отвечает «No module named pip»). Ставить пакеты нужно через
`<студия>\runtime\uv\uv.exe pip install --python <venv>\python.exe`.

### Как починить: два двойных клика

1. **`bridge\CUDA-check.cmd`** — находит студию по содержимому (папка считается
   студией, только если внутри есть `data` или `runtime`), проходит по её
   python.exe, честно запускает ядро на GPU (`torch.zeros(8).cuda()+1` и
   матричное умножение, а не «CUDA доступна») и пишет `bridge\cuda-report.txt`.
   В отчёте: версия torch, сборка CUDA, arch list, вердикт `[OK] / [БЕДА] / [!]`.
2. Если `[БЕДА]` — **`bridge\CUDA-fix-torch.cmd`**. Что он делает сам, без
   вопросов и без ввода команд:
   - проверяет, кто именно сломан (рабочие окружения не трогает);
   - закрывает студию через её же `POST /api/shutdown` — иначе Windows не даст
     заменить `torch_cuda.dll`, пока ComfyUI держит файл; ждёт до 45 секунд,
     пока освободятся порты 3210/8190/8191/8192;
   - ставит torch/torchvision/torchaudio с индекса
     `https://download.pytorch.org/whl/cu126` (последняя линейка с Pascal)
     через `uv`; если новейшая сборка cu126 всё ещё без Pascal — пробует
     проверенный набор `torch==2.8.0 / torchvision==0.23.0 / torchaudio==2.8.0`;
   - после каждой попытки **сам запускает ядро на GPU** и продолжает, только
     если оно прошло; иначе пробует следующий вариант;
   - пишет `bridge\cuda-fix-report.txt` (`fixed:` / `failed:` по каждому пути).
3. Запусти студию заново (`Start.cmd`) — уже запущенный ComfyUI держал старый
   torch в памяти. Генерация должна пойти.

Скачается ~2.5–3 ГБ, поставится ~7 ГБ: окно нельзя закрывать до строки
`---- done ----`.

### Чего делать не надо

- **Не запускай заново `Install AstraForge.cmd` с очисткой ComfyUI** — он
  поставит `cu128` обратно. Обычный запуск студии фикс не отменяет: установщик
  ставит torch только если `import torch` падает, а после фикса он не падает.
- **Не ищи виноватого в драйвере** и не переустанавливай CUDA Toolkit: ядро не
  находится потому, что его нет в файле, а не потому, что «CUDA сломана».
- **`TORCH_CUDA_ARCH_LIST` при запуске не помогает** — он влияет только на
  компиляцию, а torch уже собран.

### Второй, редкий случай: падает только текстура

Если после фикса модель **строится**, а падает покраска, и в стеке видно
`PyInit_custom_rasterizer_kernel` — это готовый wheel `custom_rasterizer`,
собранный под Ampere и новее, и его надо пересобрать под `6.1` (нужны CUDA
Toolkit 12.x и MSVC Build Tools):

```
python bridge\cuda_check.py fix-rasterizer --python "<venv>\python.exe" --arch 6.1
```

**К студии это не относится.** Её путь — геометрия: `AstraForgeMesh` (Marching
Cubes) в её ComfyUI, а покраска идёт отдельным шагом (`paint_from_concept`) в
Blender. Растеризатор нужен только внешнему `ComfyUI-Hunyuan3DWrapper` в
отдельно установленном ComfyUI.

Пришли `cuda-fix-report.txt` — по нему видно, что поставилось и что ответило
ядро, и следующий шаг будет без гадания.

## 7. Окно «Подключения»: ключи, провайдеры и что из этого нужно мосту

В студии есть окно **«Подключения»** (`http://127.0.0.1:3210` → шестерёнка).
Там три вкладки провайдеров текстовой модели — **Локальная LLM**, **OpenAI**,
**Anthropic** — и поля «Имя модели» / «API-ключ».

### Что эти ключи на самом деле делают

Это ключи **провайдера**, а не доступ к студии и не доступ для меня. В коде
студии (`server/llm.mjs`, `server/vault.mjs`) они уходят ровно в одно место:

```
POST https://api.openai.com/v1/chat/completions
Authorization: Bearer <ключ>
```

и используются **только** чат-ассистентом внутри студии: он умеет предложить
материал, перемещение/поворот/масштаб, эффект, анимацию и уточнённый промпт
для SDXL. Генерация моделей, чекпоинты, ComfyUI и мост к ключам отношения не
имеют — без ключа студия работает полностью, кроме своего чата.

Ключ хранится на твоём ПК средствами Windows DPAPI (`server/vault.mjs`), либо
берётся из переменных окружения `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` /
`TRIPO_API_KEY`.

### Почему придуманный ключ — плохая идея

- **Выдуманная строка** → студия просто ответит `LLM unavailable (401)`. Чат
  перестанет работать, и всё.
- **Настоящий ключ** → платный аккаунт у провайдера, и, как честно написано в
  самом окне: «Сообщения и описание сцены отправляются провайдеру». Для
  локальной студии это ровно то, чего мы избегаем.
- **Ключ в чате** — никогда: ни мне, ни кому-либо. Мне он не нужен, а хранить
  чужие секреты я не буду.

### Что выбрать на этой машине

**«Локальная LLM»** — подпись у неё «Ollama · без отправки данных в облако».
В поле «Локальная модель» — уже установленная
`hf.co/llmfan46/Qwen3.5-9B-Ultra-Uncensored-Heretic-GGUF:Q4_K_M`
(её видно в `/api/status` как `ollama.models[0]`). Ничего вводить не нужно:
ни ключа, ни аккаунта, ни интернета.

Заодно в этом же окне полезно проверить две вещи, которые к CUDA и чекпоинтам
относятся напрямую:

| поле | что выбрать | почему |
| --- | --- | --- |
| `Hunyuan3D checkpoint` | `hunyuan_3d_v2.1` (или `hunyuan3d-dit-v2-mv` для вида с нескольких сторон) | они уже скачаны, видно в `/api/status` |
| `SDXL для концептов` | `lustifySDXLNSFWSFW_v20.safetensors` | он есть, а `sd_xl_base_1.0` в твоём списке отсутствует — если в поле осталась база, студия скажет «Text input requires an installed SDXL checkpoint» |

### А где тогда «ключ для тебя»

Мой доступ к студии — не из этого окна, а из моста. Ключ там один и он уже
есть: **токен**, который печатается в окне `Start studio link.cmd`:

```
   link https://quiet-lake-1234.trycloudflare.com Kd8x…
                                             ^^^^^ — это и есть ключ
```

- лежит в `D:\geo2011\bridge\.link\token.txt` (24 случайных байта, ~32
  символа), папка `.link` в git не попадает;
- **не меняется между запусками**: файл переиспользуется, поэтому токен
  постоянный, а меняется только адрес туннеля;
- хочешь свой — впиши в этот файл одну строку **не короче 16 символов**
  (например `astraforge-warsaw-2026`), сохрани в UTF-8 и запусти мост снова.
  Своё слово короче и слабее случайного, так что делать это стоит только для
  удобства, а не «для надёжности»;
- любой запрос без этого токена получает `403`, и больше никакой защиты в
  мосте нет — поэтому токен не публикуй и в чат не вставляй ничего другого.

## 6. Студия не видит новый чекпоинт (например `lustifySDXLNSFWSFW_v20.safetensors`)

Порядок проверки — от дешёвого к дорогому. Все проверки браузерные, консоль не
нужна: это обычные GET-адреса, открываются в новой вкладке.

**Шаг 0. Убедись, что это вообще тот список.** В студии есть два разных списка
моделей, и они не пересекаются:

| что выбираешь | откуда список | что там может быть |
| --- | --- | --- |
| «Модель помощника», «Модель просмотра текстур и анимации» | **Ollama** (`127.0.0.1:11434`) | только GGUF-модели, имена вида `hf.co/…Q4_K_M` |
| «SDXL для концептов» (раздел «Связи») | **ComfyUI** (`127.0.0.1:8190`) | только `*.safetensors`/`*.ckpt` из `models\checkpoints` |

`.safetensors` в списке Ollama не появится никогда — это разные движки.
И наоборот: GGUF не появится в списке ComfyUI.

**Шаг 1. Куда класть файл.** Комфортно в любое из двух мест — студия при запуске
пишет `D:\AstraForge\data\runtime\models.yaml` и передаёт его ComfyUI
(параметр `--extra-model-paths-config`), а в нём прописаны обе базы:

* `D:\AstraForge\data\models\checkpoints\`
* `D:\AstraForge\runtime\comfy\models\checkpoints\`

**Шаг 2. Список строит не студия, а ComfyUI.** Студия только *читает* его
(`ImageOnlyCheckpointLoader → ckpt_name`), а ComfyUI кэширует список моделей на
старте. Поэтому добавленный файл появляется после перезапуска движка, а не
после F5. Что видит кто — видно в браузере:

* `http://127.0.0.1:8190/object_info/ImageOnlyCheckpointLoader` — сырой список ComfyUI;
* `http://127.0.0.1:3210/api/status` — то, что видит студия (`comfy.checkpoints`).

| ComfyUI | студия | что делать |
| --- | --- | --- |
| файла нет | — | файл не в той папке, или ComfyUI не перезапускался |
| файл есть | файла нет | обновить страницу студии / перезапустить студию |
| файл есть | есть | выбрать его в «Связи → SDXL для концептов» и сохранить |

**Шаг 3. Перезапуск ComfyUI.** Студия держит его дочерним процессом:
pid лежит в `D:\AstraForge\data\runtime\comfy.pid`, лог —
`D:\AstraForge\data\runtime\comfy.log`. Проще всего выключить и снова
включить движок в студии (или закрыть и открыть студию). Не убивай python.exe
наугад: под ним может быть ещё что-то.

**Шаг 4. Размер файла.** `lustifySDXLNSFWSFW_v20.safetensors` — **≈6.94 ГБ**.
Если в проводнике 1–2 КБ, это HTML-заглушка с Hugging Face (бывает на
gated-репозиториях): ComfyUI такой файл покажет, а загрузка упадёт. Скачивать
надо на huggingface.co, войдя в аккаунт и приняв условия.

**Оговорка про MV-Adapter.** База `sd_xl_base_1.0.safetensors` должна остаться
на месте: она зашита в `views_mvadapter.mjs` (`MVA_CHECKPOINT`), и Views без неё
не соберётся. Любой другой SDXL-чекпоинт добавляется **рядом**, а не вместо.
