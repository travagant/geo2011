# d3studio — студия ассетов (полный режим)

Локальная студия для игровых ассетов: концепт на своей видеокарте → 3D-модель → glTF →
**пакет для Godot или Unity**, который открывается в движке без ручной уборки файлов.

Решение владельца 09.11.2026: студия развивается **по Godot и Unity**. Экспорт в родные
файлы Disciples 3 (`.g`, `.scene`, `.ac`, `.a`) **отложен**: формат до конца не известен,
изменённый ванильный юнит роняет игру — рисковать релизом незачем. Мост остался в коде
(`server/experimental/d3tool.mjs`, тесты идут), но к студии не подключён и в интерфейсе не
показывается; вернуть его — три строки в `server/index.mjs`.

## Откуда взялось

Основа — релиз **AstraForge 0.3.0** (MIT, `github.com/Snodrod/AstraForge`, тег `v0.3.0`):
сервер на Express, интерфейс на React, конвейер 3D (Hunyuan3D/Pixal3D через ComfyUI, мосты в
Blender и Godot). Лицензия MIT разрешает брать код за основу и переделывать его под себя при
условии сохранения уведомления об авторских правах — оно лежит рядом в `LICENSE` и
`THIRD_PARTY_NOTICES.md`, а исходные документы базовой версии — в `docs/base/`.

Что мы переделали (и почему):

| Что | Как было | Как у нас |
|---|---|---|
| Назначение | Godot-пакеты, спрайты, эффекты «как есть» | своя студия ассетов: Godot **и** Unity, один и тот же меш |
| Unity-экспорт | не было совсем | `POST /api/unity/export` → `.zip` с `Assets/<Имя>/` (модель, текстуры, манифест, README) — `server/unity.mjs` |
| Disciples 3 | не было | отложено: модуль в `server/experimental/`, от студии отключён |
| Имя, версия, подпись | AstraForge 0.3 | d3studio 0.3.1 |
| Запуск | `Start.cmd` их установщика | любой Node ≥ 20, см. ниже |

## Запуск

```bash
npm ci                      # один раз: 111 пакетов
npm start                   # http://127.0.0.1:3210
npm run dev                 # то же, но с горячей перезагрузкой интерфейса
npm test                    # node --test tests/*.test.mjs
```

Студия слушает только `127.0.0.1` и отказывает запросам с чужим `Host`/`Origin`, а на изменения
требует заголовок `x-astra-client` (его ставит `src/api.js`) — так было в базовой версии, и это
правильно для приложения без паролей.

## Unity: что именно уезжает в движок

`POST /api/unity/export {"assetId": "…", "textures": ["…"]}` собирает один `.zip`:

```
Assets/Knight-of-Death/
  Models/Knight-of-Death.glb     — та же геометрия, что в студии, побайтово
  Textures/Knight-skin.png       — если переданы id текстур
  d3studio.bundle.json           — откуда модель, размеры, sha256 каждого файла
  README.txt                     — шаги импорта: glTFast, Scale Factor = 1, конверсия материалов
```

В манифест и в `README.txt` пакета попадает **проверка модели** (`server/mesh-check.mjs`):
треугольники, вершины, дубликаты после сварки, есть ли UV и нормали, скелет, клипы, границы,
неравномерный масштаб узлов. Модель с блокером (пустая, не треугольники, больше 2,5 млн
треугольников) **не пакуется** — возвращается 400 с причиной.

Ответ: `{id, name, url, output, files, mesh, bytes}`; `url` отдаёт архив обычным
`GET /api/exports/<id>` с именем файла. Требования к модели — `.glb`, `.gltf`, `.obj`
(`GET /api/unity/formats`), остальное отклоняется с текстом, а не пустым архивом. Имя папки
санитизируется и транслитерируется (`Боец с копьём` → `Boec-s-kopem`), потому что кириллица в
путях Unity ломается на части платформ и в сборках.

Проверки: `tests/unity.test.mjs` — состав архива, байты модели, манифест, текстуры, отказы.
Живой прогон: архив скачивается, внутри 4 файла + манифест, 2,5 КБ на пустышке.

## Что ещё не переписано

Базовая версия велика: ~7 200 строк сервера и ~13 500 строк интерфейса. В этом заходе сделано
самое нужное — своё имя, Unity-пакет, тесты к нему, отключение Disciples; остальное лежит как
есть и переделывается по мере надобности:

* брендинг внутри i18n (`src/i18n/*.json`), `x-astra-client` → наш заголовок (5 файлов + 2 теста);
* установщик (`installer/`, `ai/skills`, `data/runtime/custom_nodes`) — материал базовой версии,
  студия работает и без него, если ComfyUI и модели уже стоят;
* Unity-пакет в мастере пока отдельным блоком на шаге «Экспорт», а не профилем экспорта рядом с Godot
  (профиль потребует шага в конвейере Кузницы);
* нативная часть: собран только первый шаг (`d3mesh verify`), остальные по плану — `docs/studio/NATIVE.md`;
* Godot-пакет (`forge-pipeline.mjs`, профиль `godot`) — базовый, наш ещё не переписан.
